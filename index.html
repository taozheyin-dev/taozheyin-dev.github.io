04 / Wisdom

实战经验与工程洞察

在 20+ 项目与多款 AI Agent 深度博弈中总结的 6 条第一性原理与工程心法。

🎯

工具选择的“解耦与卡位”

不要迷信单一全能 Agent，而是像搭积木一样为每个工具设立明确的职责边界：

  • 复杂系统架构：依赖 Claude Code 的长程一致推理；
  • 敏捷原型验证：选择 ChatGPT Responses API 的极致响应；
  • 海量代码审查：交由 Kimi Code 强大的长上下文吞吐；
  • 多模型综合编排：以 ZCode 作为统一调度工作区。
🔧

自建 API 网关的“主权价值”

网关不仅是格式转换器，更是应对大模型供应链风险的防御性基础设施：

  • 协议自由：统一 Chat / Responses / Messages 三协议无缝互通；
  • 体验把控：自研流式管道重构，抹平各服务商首字延迟差；
  • 稳定性对冲：多 Key 轮转与动态探测，彻底对冲供应商宕机与限流。
⚙️

大规模配置的“代码化治理”

管理 34 个渠道、81 个模型绝不能依赖图形界面点选：

  • Git 追踪变更：全部路由策略、上下文配额纳入版本化管控；
  • 自动化回归测试：配置改动必须经过脚本语法与连通性验证；
  • 状态定期持久化：关键运行时状态通过 SQLite 镜像归档备份。
🐛

诊断调试的“日志驱动与变量隔离”

大模型输出具有不确定性，排障时“凭借感觉猜测”是最大禁忌：

  • 审计日志抓包：善用底层 logs.sqlite3 等数据库精准定位真实载荷；
  • 三次失败重思考：凡尝试两次未果，立刻停下并回归第一性原理；
  • 严格单一变量：逐个剔除网络代理、系统提示词与模型参数干扰。
🤝

开源协作的“敬畏心与交付标准”

参与开源社区不是提交草稿，而是展现工程师严谨素养的舞台：

  • 深度使用在先：充分吃透上游架构设计逻辑后再动笔贡献；
  • 交付三位一体：高质量 PR 必须由干净代码、单元测试与清晰文档共同组成；
  • 数据说话：尊重维护者建议，在 Issue 和 Code Review 中用实测数据沟通。
📈

持续优化的“量化指标意识”

没有数字量化的优化只是心理安慰，必须设立明确的性能基准：

  • 延迟敏感：持续监控 TTFB、流式 Chunk 耗时并做毫秒级优化；
  • 资源与成本量化：关注边缘算力利用率（如 CF D1 仅耗 0.09% 配额）；
  • 技术债务归零：定期审视废弃代码分支与旧版依赖，紧跟 upstream 演进。
