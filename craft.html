03 / 工作方法

让工程细节，经得起使用。

从接口边界到日常体验。
让每一步都有明确的理由。

01

先把边界说清楚

先明确输入、输出和失败方式，再写适配。不同协议的差异应有固定的处理位置。

02

用证据缩小问题

从日志和实际载荷出发，构造能复现问题的最小场景，每次只改变一个关键变量。

03

让配置可以追踪

把模型、路由与环境配置纳入版本管理，保留变更原因，也为回退留下路径。

04

交付包含验证

根据改动检查关键行为，记录限制和使用方式，让下一次维护有据可依。

CodeBuddy2API · 协议转换网关

API 与服务 / 工程实践

CodeBuddy2API

协议转换网关

系统流程示意

要解决的问题

不同工具使用 Chat Completions、Responses 和 Messages 等接口。协议、事件格式与版本差异，让接入和维护变得重复。

我的贡献

  • 参与多协议适配，把请求参数和响应事件的转换集中在网关边界。
  • 调整流式处理链路，让响应片段能够边接收、边解析、边输出。
  • 处理跨版本迁移与兼容问题，维护已有调用方式。

实现结果

调用侧可以沿用熟悉的接口，适配工作集中在网关中；后续升级也有了更明确的检查边界。

工程取舍

统一协议不能抹平所有差异。工具调用、错误事件和流式结束语义仍需分别检查，避免表面兼容、实际行为不同。

ZCode · 多模型开发环境

开发环境 / 工程实践

ZCode

多模型开发环境

系统流程示意

要解决的问题

模型与渠道逐渐增加后，上下文长度、输出限制和路由规则容易不一致。社区技能也需要筛选，才能适应日常任务。

我的贡献

  • 整理 Provider 和模型配置，逐项校准上下文、输出限制与思考档位。
  • 梳理路由与回退关系，处理循环转发的配置风险。
  • 筛选、去重和整理技能，把配置变更纳入版本管理。

实现结果

环境的模型能力、路由关系和技能用途更清楚，定位配置问题时有了可以对照的记录。

工程取舍

更多接入意味着更多维护工作。优先保留用途清楚、能够持续验证的配置，减少无效选项。

NIM Proxy · 并发代理与稳定性

API 与服务 / 工程实践

NIM Proxy

并发代理与稳定性

系统流程示意

要解决的问题

并发竞速可以改善等待体验，但多个协程同时返回时，状态清理和响应归属容易出现竞争。凭证状态也影响请求的稳定性。

我的贡献

  • 定位模型竞速流程中的竞态问题，修复并发状态处理。
  • 维护凭证池与健康轮转逻辑，整理失败和重试的处理路径。
  • 运行相关回归测试，并补齐日常使用中的中文交互。

实现结果

并发响应与失败处理有了更明确的归属，相关修复经过回归验证。

工程取舍

请求竞速会增加上游消耗，需要同时考虑取消、清理与重试的边界，不能只关注最快的一次返回。

边缘邮箱 · Cloudflare 邮件服务

边缘服务 / 工程实践

边缘邮箱

Cloudflare 邮件服务

系统流程示意

要解决的问题

一个轻量邮件服务需要接收、保存和查询消息，同时控制部署与运维成本。

我的贡献

  • 组合 Cloudflare Workers、D1 和 KV，完成邮件接收与查询链路。
  • 整理部署配置，处理实际使用中的邮件接收与域名配置问题。
  • 观察数据库与边缘资源用量，控制日常运行成本。

实现结果

邮件处理流程落在可独立部署的边缘服务上，无需维护常驻服务器。

工程取舍

Serverless 降低了日常运维负担，也引入平台配额与运行时限制。存储和查询方式需要围绕这些约束设计。

GitHub 账号管理器 · 开发身份与凭证隔离

开发环境 / 工程实践

GitHub 账号管理器

开发身份与凭证隔离

系统流程示意

要解决的问题

同一台机器上的多个 GitHub 身份，需要正确使用提交信息和访问凭证。手动切换容易遗漏，也很难长期保持一致。

我的贡献

  • 利用 Git includeIf 按目录选择提交身份，配合 SSH 配置隔离访问凭证。
  • 集成 OAuth Device Code 授权流程，整理终端侧的账号操作。
  • 通过相关测试检查账号切换与凭证管理的关键路径。

实现结果

工作目录与 Git 身份建立对应关系，日常操作减少了对手动切换的依赖。

工程取舍

提交身份与仓库访问权限是两条独立链路，需要分别验证，不能仅凭一次推送成功判断配置完整。

AI 服务导航 · 轻量资源入口

AI 工具 / 工程实践

AI 服务导航

轻量资源入口

系统流程示意

要解决的问题

服务和资源分散在不同入口。一个日常可用的导航页，需要清楚的分类、直接的访问路径与轻量的加载体验。

我的贡献

  • 整理服务分类和资源入口，使用原生 HTML、CSS 与 JavaScript 实现。
  • 完成静态站点部署，把维护范围控制在内容与交互本身。
  • 持续整理页面结构，让资源查找路径更直接。

实现结果

形成一个无需应用服务器的资源导航入口，内容更新和页面维护更直接。

工程取舍

导航的长期价值来自资源质量和维护。页面保持轻量，把注意力留给分类与链接的有效性。
